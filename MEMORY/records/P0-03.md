## What was built

- `.github/workflows/ci.yml` with two jobs:
  - `verify` -- `install`, `lint`, `typecheck`, `unit tests`, `build`;
  - `integration` -- `needs: verify`; runs `pnpm test:integration` with
    Testcontainers on the runner's Docker daemon.
- `eslint.config.js` -- baseline flat config (`typescript-eslint`
  recommended) so `pnpm lint` has something to run; `P0-11` extends it.
- pnpm store caching through `actions/setup-node`'s `cache: pnpm`;
  `concurrency` cancels superseded runs on the same ref.

**CI verified green on GitHub Actions**, not only locally: run
`35583091214` (https://github.com/zed378/image-management/actions/runs/35583091214),
`verify: success`, `integration: success`. That run also proves the
Testcontainers harness from `P0-02` works on a Linux runner, not just on
Docker Desktop for Windows.

## Deviations from the spec

- **Integration is a merge-blocking job**, where the task allowed it to be
  "a separate, allowed-to-be-slower job". It is separate and slower, and
  runs after `verify`; it was made blocking because tenant isolation
  (`P1-06`) and storage conformance (`P0-07`) live in integration tests, and
  neither may be advisory.
- **Branch protection is documented, not applied.** It is a GitHub
  repository setting; the task anticipated this ("applied by a repo admin,
  out of band").

## Decisions worth recording

- CI status is verified by polling the public GitHub REST API for the run
  matching the pushed commit SHA -- no `gh` CLI is installed in this
  environment. The API needs the **full** 40-character SHA for `head_sha`;
  an abbreviated one silently returns no runs.
- Task branches are pushed only when a Definition of Done requires CI
  evidence, and deleted from the remote on merge.
