&& pnpm build` -- 15/15 typecheck tasks, 15/15 test files, 2/2 builds.

## Deviations from the spec

1. **Two deployables, not five services.** The task and
   `docs/ARCHITECTURE/02` named `api-gateway`, `asset-service`,
   `image-processing-service`, `storage-service`, `search-service`. Built
   instead: `services/api` + `services/worker` + libraries. Recorded as
   `ADR-017`; the logical boundaries survive as package/module boundaries
   enforced by lint and `dependency-cruiser` (wired in `P0-11`).
2. **More packages than listed.** The task named `schema`, `storage-adapter`,
   `config`, `logger`; the full set above follows
   `docs/ENGINEERING/00-CODING-CONTEXT.md`.
3. **No build step for packages** (`ADR-018`): packages export TypeScript
   source; only services (and later SDKs) build.
4. **TypeScript pinned to 5.9.3**, not the current 7.0, because
   `typescript-eslint` 8.70 declares `typescript <6.1.0` (`ADR-018`).

`docs/ENGINEERING/00`, `01`, `02`, `04` were corrected to match: they still
described five services and `NodeNext` resolution.

## Decisions worth recording

- `ADR-017` -- deployable topology.
- `ADR-018` -- just-in-time packages, bundler resolution, TypeScript pin.
- pnpm 11 renamed `onlyBuiltDependencies` to `allowBuilds`; native-binary
  packages (`sharp`, `esbuild`, `unrs-resolver`, `simple-git-hooks`) are
  allow-listed there and everything else is denied.

each package gains real code. No security-critical test applies yet.
