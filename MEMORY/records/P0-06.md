## What was built

- `packages/db`: `createDb()` (Kysely over a `pg` pool with a per-connection
  statement timeout and application name), `migrateToLatest()`,
  `migrateDownOne()`, row types in `types.ts`, DDL helpers.
- Migration `20260921T0900_create_tenancy_chain`: `tenants`, `users`,
  `applications`, `projects`; `citext`; the `set_updated_at()` trigger.
- **Composite foreign keys**: `projects (application_id, tenant_id) ->
  applications (id, tenant_id)`; `(id, tenant_id)` unique on applications and
  projects as targets for every later child table.
- `packages/schema`: `newId()` (monotonic ULID), `isUlid()`, `ULID_PATTERN`.
- `services/api/src/migrate.ts`, bundled to `dist/migrate.js`;
  `pnpm db:migrate` locally. Verified against the compose database: applies
  once, then reports "already up to date".
- `packages/test-utils/src/database.ts`: `createTestDatabase()` -- a fresh,
  migrated database per test file, dropped afterwards.

## Deviations from the spec

- **Kysely, which the spec did not list** (Prisma/Drizzle/Knex). Recorded as
  `ADR-019`, with the `scoped()` properties as the deciding criterion.
- **ADR numbering:** `docs/ENGINEERING/00` had provisionally named Fastify
  `ADR-019` and Kysely `ADR-020`. Since this task decided Kysely first and the
  log is chronological, Kysely is `ADR-019` and Fastify becomes `ADR-020`
  (`P0-08`); every reference was swapped.
- Users carry a tenant-wide `role`; finer per-application/per-project grants
  are a `role_assignments` table in `P1-01`.

## Decisions worth recording

- `ADR-019` -- Kysely + pg, static migration registry.
- ULID shape enforced by a `CHECK` on every primary key, not only in code.
- `int8` parsed to numbers globally (every value < 2^53).
- Migrations live in `src/` and are imported statically so the production
  image runs them without `tsx`.
