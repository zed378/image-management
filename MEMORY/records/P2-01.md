- **Date:** 2026-09-21
- **Author:** Agent session (Claude Opus 5, Claude Code)
- **Branch / PR:** `feat/P2-01-object-naming`, squash-merged to `main`
- **Implements:** `docs/STORAGE/03-BUCKET-STRATEGY.md`, `docs/STORAGE/04-OBJECT-NAMING.md`

## What was built

- **Step 1** -- `packages/storage-adapter/src/object-keys.ts`:
  `originalObjectKey` (`{tenant}/{project}/originals/{asset}/{version_id}.{ext}`),
  `derivativeObjectKey` (`.../derivatives/{asset}/{version_id}/{params_hash}.{ext}`),
  `derivativePrefix`. Every segment must be a ULID or lower-case hex, so no
  caller input can reach a key.
- **Step 2** -- `packages/transform-params`: the complete canonicalizer of
  `docs/IMAGE-DELIVERY-PROTOCOL/03` (all 14 steps) over the full parameter
  table of `IDP/04`: aliases and dialects as data (`vocabulary.ts`), CSS
  named colors, the interaction matrix, `auto` resolution (Accept bucket,
  versioned quality table, EXIF orientation, an injected gravity resolver),
  snapping, pixel budget; `computeParamsHash`; `bucketFromAccept`.
- **Step 3** -- one bucket (root) per environment, isolation by prefix;
  `docs/STORAGE/03` Final with the reasons and controls.
- `ADR-023`: the hash function and encoding, table versions in the hash
  input, delivery parameters outside the hash, the tuned near-miss rule,
  and the canonical-form details the parameter table left open.

## Definition of Done evidence

- `docs/STORAGE/04` is Final with the exact key scheme and the hash algorithm
  written out (input string, function, truncation), plus a worked example
  whose hash is the first golden vector.
- Tests (83 in transform-params, 4 in object keys): both reference examples
  of IDP/03 and IDP/04 canonicalize to the documented form; the five
  dialect spellings hash identically; parameter order and duplicates do not
  change the hash; every rejection row of IDP/03 (field and reason); the
  interaction matrix; defaults; `auto` resolution; snapping; delivery
  parameters outside the hash; 14 append-only golden vectors.

## Deviations

- P2-01 asked for "hash (e.g. SHA-256, truncated)" -- fixed by ADR-023. The
  full normalizer (planned for `P3-02`) was needed here to produce real
  hashes; `P3-02` now tunes it against the engine and extends near-miss
  tests to every known-name pair.
- The quality table values are provisional until `P3-01`'s benchmark; they
  are versioned (`q1`), so setting real values bumps the version and
  re-keys derivatives, as ADR-014 requires.

## Found and fixed

- IDP/03's near-miss rule ("edit distance <= 2") contradicted its own
  foreign-parameter examples (`v`, `t` are within distance 1 of `w`/`f`).
  Tuned by name length (ADR-023) and the open question updated.
