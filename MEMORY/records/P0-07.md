# P0-07: Storage abstraction interface + provider adapters

- **Date:** 2026-09-21
- **Author:** Agent session (Claude Opus 5, Claude Code)
- **Branch / PR:** `feat/P0-07-storage-adapters`, squash-merged to `main`
- **Implements:** `docs/STORAGE/00-STORAGE-ARCHITECTURE.md`, `01-STORAGE-ABSTRACTION.md`, `10-STORAGE-PROVIDER-ADAPTER.md`

## What was built

`packages/storage-adapter`:

- The `StorageAdapter` interface with declared `capabilities`, shared key
  validation (the path-traversal defence), and five error classes that every
  provider's failures are translated into.
- Six adapters: **`local`** (the default; also serves NFS, SMB/CIFS, EFS,
  Azure Files and any mounted network filesystem), **`s3`** (AWS S3, R2,
  MinIO, Wasabi, B2, Spaces, Ceph, GCS interop), **`azure-blob`**,
  **`sftp`**, **`webdav`**, and `memory` for unit tests.
- `withProxyPresign()` + `createProxyToken()`/`verifyProxyToken()`: HMAC
  tokens that bind key, method, expiry, content type and maximum size, so
  presigned upload/download works on providers that cannot sign.
- `createStorageAdapter(config)` -- the one place a provider is chosen.

`packages/config`: `STORAGE_PROVIDER` now defaults to `local`, with variables
and cross-field rules for all five providers, and production refuses to start
on `local` without an explicit `STORAGE_LOCAL_ROOT`, or on `sftp` without a
pinned host key.

## Deviations from the spec

**The scope changed mid-task at the product owner's request** (2026-09-21):
"default storage should be local, the disk currently in use; also support
NFS, object storage and other storage reachable over a network or the
internet". The task originally asked for an S3 adapter tested against MinIO.
Delivered instead: the five providers above, all tested against real servers.
Recorded as `ADR-021`, which supersedes `ADR-002`. The task text in
`TASKS/PHASE-0-FOUNDATION.md` was rewritten to match what was built.

## Decisions worth recording

- `ADR-021` -- local default, NFS-via-mount, five providers, proxy presign,
  declared capabilities.
- Filesystem-like providers (local, SFTP, WebDAV) store content types in
  `.meta/` sidecars; atomic writes are temp-file + rename (MOVE for WebDAV,
  posix-rename for SFTP).
- List cursors are opaque by contract; the filesystem-like adapters use a
  base64url-encoded last key, S3 and Azure use their native continuation
  tokens. The conformance test never inspects a cursor.

## Bugs the conformance suite found

Before any caller existed:

1. **Local streamed writes hung forever**: `createWriteStream({ autoClose:
   false })` never emits `close`, so `pipeline()` never resolved. Fixed with
   `createWriteStream(..., { flush: true })`, which also fsyncs.
2. **Windows refuses to rename over a file a reader has open** (`EPERM`).
   Fixed with a bounded, backed-off retry (the `graceful-fs` approach); Linux
   and NFS were never affected.
3. **WebDAV `stat` validated the key inside its `try`**, so a hostile key
   surfaced as `StorageUnavailableError` instead of `StorageKeyError`.
4. Two test-harness problems, not adapter bugs: Azurite's startup log line
   differs from the documented one, and the WebDAV image has no shell (so the
   port-probe wait strategy cannot run) and no `/data` directory (every MKCOL
   returned `409 Conflict`).

## Tests added

- `packages/storage-adapter/tests/conformance.ts` -- the 23-case suite:
  round-trip, streaming, overwrite, atomicity under a concurrent reader,
  not-found, stat, idempotent delete, independent copy, paginated listing,
  **eleven hostile key shapes** (traversal, absolute, backslash, NTFS stream,
  device names, control characters, hidden segments...), and presigned
  upload/download including expiry.
- Run against: `local` (unit), `memory` (unit), MinIO, Azurite, OpenSSH
  (`atmoz/sftp`), `hacdias/webdav` -- **138/138 passing**.
- `src/proxy-presign.test.ts` (17): forged key, raised size limit, wrong
  secret, wrong method, expiry, unsafe key inside a valid signature,
  malformed tokens, short secret.
- `src/keys.test.ts` (19); config tests for every provider's rules and the
  production requirements (30 with the boot tests).
