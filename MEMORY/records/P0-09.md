# P0-09: Error handling + error-code taxonomy

- **Date:** 2026-09-21
- **Author:** Agent session (Claude Opus 5, Claude Code)
- **Branch / PR:** `feat/P0-09-error-handling`, squash-merged to `main`
- **Implements:** `docs/API/05-ERROR-HANDLING.md`, `docs/ENGINEERING/06-ERROR-RESPONSE-STANDARDS.md`

## What was built

- `packages/errors/src/codes.ts` -- `ERROR_CODES`, the single registry:
  every wire code with its HTTP status, retryability and generic message
  (`as const satisfies Record<string, ErrorCodeSpec>`, so `ErrorCode` is the
  closed union of keys). `isErrorCode()` uses `Object.hasOwn` so
  `"toString"` is not a code.
- `packages/errors/src/app-error.ts` -- `AppError(code, { message, details, cause })`.
  Status and retryability come from the registry, never from the call site.
  `expose` is `status < 500`; `publicMessage` returns the specific message
  for a 4xx and the registry's generic one for a 5xx.
- `services/api/src/http/error-handler.ts` -- the only place an error
  becomes a status and a body: `AppError` -> registry; `ZodError` and route
  schema (ajv) failures -> `400 validation_failed` with `{ field, reason }`
  only; `FST_ERR_CTP_*` and JSON syntax errors -> `payload_too_large`,
  `unsupported_media_type`, `malformed_json`; everything else ->
  `500 internal_error`. 4xx logs at `warn`, 5xx at `error` with the cause;
  a retryable 503 gets `Retry-After: 5`.
- `respond.ts#sendError` now takes an `ErrorCode`; `/readyz` and the 404
  handler use it.
- `scripts/error-codes-table.ts` generates the taxonomy table in
  `docs/API/05` from the registry, so the doc cannot drift from the code.

Tests: `packages/errors/src/codes.test.ts` (every code snake_case, 4xx/5xx,
sentence-case message; every 5xx except `internal_error` retryable; rate
limit vs quota; `AppError` behavior) and
`services/api/tests/error-handling.test.ts` (10 cases, including that a
secret in an unknown error's message and in a 5xx `AppError`'s message never
reaches the body, and that Zod details never echo the received value).

## Deviations from the spec

- `docs/ENGINEERING/06` described one subclass per status
  (`NotFoundError`, `ConflictError`, ...). Implemented instead as one
  `AppError` driven by the registry: a subclass per status lets a call site
  pair a code with the wrong status, which the registry makes impossible.
  `ENGINEERING/01`, `04`, `05`, `06`, `07`, `09`, `13`, `14` were updated to
  the registry form.
- `ENGINEERING/06`'s example handler was Express; replaced with the real
  Fastify handler.

## Decisions worth recording

- The registry is keyed by the wire code itself (`ERROR_CODES.asset_not_found`),
  an explicit exception to the `UPPER_SNAKE_CASE` key rule in
  `ENGINEERING/01`, because the key *is* the public contract.
- Zod's `issue.code` is used as `reason`; `issue.message` is never used,
  since it can quote input.

## Bugs found and fixed

None beyond the doc drift above.

## Follow-ups

- Domain codes are registered ahead of the modules that throw them; a
  module adding a new code adds it to the registry and regenerates the
  `docs/API/05` table (`pnpm tsx scripts/error-codes-table.ts`).
