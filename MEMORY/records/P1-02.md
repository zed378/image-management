# P1-02: API key issuance & hashed storage

- **Date:** 2026-09-21
- **Author:** Agent session (Claude Opus 5, Claude Code)
- **Branch / PR:** `feat/P1-02-api-keys`, squash-merged to `main`
- **Implements:** `docs/SECURITY/04-API-KEY-MANAGEMENT.md`, `docs/DATABASE/13-API-KEYS.md`, `docs/API/02-AUTHENTICATION.md`

## What was built

- `services/api/src/modules/api-keys/` -- the first real domain module:
  `api-key.crypto.ts` (format `ak_<env>_<ULID>_<43 base64url>`, HMAC-SHA256
  over `id.secret` with `API_KEY_PEPPER`, constant-time verify, decoy hash),
  `.repository.ts` (scoped reads/writes; never selects `key_hash`),
  `.authentication.ts` (the pre-tenant lookup and the batched
  `last_used_at` write, via `unsafeUnscoped` with typed reasons),
  `.service.ts` (create, list, get, rotate with overlap, revoke,
  authenticate), `.schema.ts`, `.mapper.ts`, `.types.ts`,
  `last-used-tracker.ts`.
- `services/api/src/modules/tenancy/` -- application/project reads and
  `provisionTenant`; `services/api/src/provision.ts` -- the operator CLI
  that creates a tenant, application, project and bootstrap key (bundled as
  `dist/provision.js`, `pnpm provision`).
- **`packages/db` `scoped()` and `unsafeUnscoped()`** -- pulled forward from
  `P1-05` so the first repository could use the only door from line one.
  A Kysely plugin rewrites the final query tree: tenant (and project)
  predicates ANDed onto SELECT/UPDATE/DELETE; INSERTs without the context's
  ids rejected. Survives `.where()`, `.clearWhere()`, and replaced
  `.values()` (unit-tested on compiled SQL).
- **`packages/tenancy` `TenantContext`**, `systemContext`, `inProject` --
  pulled forward from `P1-04` (the permission matrix itself stays there).
- Config: `API_KEY_PEPPER` (required, >= 32 chars, a `dev-only-` value
  refused in production), `credentialsFragment`, `refineCredentials`.
- `packages/test-utils` `seedTenant` / `seedProject` / `seedApplication`.
- `packages/db`: `Tx` and `Executor` types exported.

## Definition of Done evidence

- **No code path can retrieve a plaintext key after creation** --
  `api-keys.int.test.ts` reads the raw row (`select *`) and asserts neither
  the secret nor the plaintext appears in any column; a second test asserts
  `get`, `list` and the create result's `apiKey` contain neither the secret
  nor the stored hash.
- **A revoked key immediately fails authentication** -- tested: the key
  authenticates, is revoked, and the very next `authenticate` returns null.
  Also tested: rotation overlap (old key valid until `now + overlap`, then
  not), every failure mode returns the same null, suspended application or
  tenant, cross-tenant access answers `api_key_not_found` and changes
  nothing, `last_used_at` written only by the tracker's flush.
- Verified end to end: the built `dist/migrate.js` and `dist/provision.js`
  against the compose PostgreSQL issue a working key, printed once.

## Deviations from the spec

- HTTP routes for key management are mounted in `P1-03` with the
  authentication middleware (they need a caller); P1-02 delivers the
  service, the lookup, and the `provision` bootstrap. `docs/API/02` states
  both. The `ENGINEERING/05` layer-template rewrite moves with the routes to
  `P1-03`, where the full vertical slice exists.
- `scoped()` (P1-05) and `TenantContext` (P1-04) built here; those tasks now
  add the IDOR suite, the permission matrix and the request wiring.
- Permission names are shape-checked (`PERMISSION_PATTERN`) until `P1-04`
  defines the closed vocabulary.
- Audit entries for create/rotate/revoke are `P1-07`'s.

## Decisions

- ADR-022 point 4 (HMAC + pepper) implemented as specified; the pepper is
  not rotated on a schedule (resolved in `docs/DEVOPS/04`: rotating it
  invalidates every key; compromise alone reveals none).
- `unsafeUnscoped` credential call sites are not logged per call (they run
  on every request); they live in `*.authentication.ts` files, outside the
  lint-restricted repository/service files. `docs/ENGINEERING/07` updated.
- ESLint `no-unused-vars` now honors a leading underscore, matching tsc's
  `noUnusedParameters`.

## Bugs found and fixed

- **CI (first push): gitleaks flagged the test pepper**
  (`test-pepper-0123456789abcdef0123456789abcdef` in `boot.test.ts`).
  Triage: a fake value used only by tests, never deployed. Allowlisted by
  exact value in `.gitleaks.toml`, per the P0-10 policy (values, never
  paths).
- **CI (first push): `packages/**` branch coverage fell to 82.1%** (< 85%).
  Closed with tests of real behavior, not padding: `refineCredentials`
  (example pepper refused in production, short pepper refused anywhere),
  `scoped()` INSERT edge cases (tenant column omitted, tenant id supplied as
  an expression, multi-row), a failing migration reporting its name. The
  twelve unreachable `?? ""` fallbacks in `toStorageConfig` were replaced by
  one explicit guard that throws if a caller skipped `refineStorage` --
  inventing an empty bucket name was the wrong failure mode anyway.

- `scoped()`'s insert type first stripped `project_id` from *every* table,
  which made `api_key_projects` (where project_id is data) impossible to
  insert; now stripped only on project-owned tables.
