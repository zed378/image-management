## What was built

- `deploy/docker-compose.yml` -- PostgreSQL 17, Redis 7.4 (AOF,
  `noeviction`), MinIO, and a one-shot `minio-init` that creates the
  `image-delivery-dev` bucket. Host ports `55432`, `56379`, `59000`/`59001`.
- `pnpm infra:up` -- waits for the three services to be healthy, then runs
  `minio-init`. Verified: exits 0, all three healthy, bucket created.
- `deploy/Dockerfile` -- one multi-stage image for either deployable via
  `--build-arg SERVICE=api|worker`; non-root, glibc base for `sharp`.
- `.dockerignore`, `.env.example` (infrastructure variables), `deploy/README.md`.
- `packages/test-utils/src/global-setup.ts` -- Testcontainers starts one
  PostgreSQL, Redis, and MinIO per integration run and passes their
  addresses to tests via Vitest `provide`/`inject`.
- `packages/test-utils/tests/infrastructure.int.test.ts` -- proves all three
  are reachable. 3/3 passing, ~8 s on Docker Desktop for Windows.

## Deviations from the spec

- **MinIO comes from `quay.io`.** The `minio/minio` repository on Docker Hub
  no longer exists (`pull access denied ... repository does not exist`,
  2026-09-21). Both MinIO images are pinned release tags on
  `quay.io/minio/*`.
- **Non-default host ports** (`5xxxx`) so the stack cannot collide with a
  developer's own PostgreSQL or Redis.
- **No mail-catcher.** The task listed it as optional ("if webhooks-to-email
  debugging is desired"); nothing in the plan needs it.
- **The DoD's health-check clause** ("a fresh clone + compose up + pnpm dev
  serves the API Gateway health check") depends on `/healthz`, which is
  `P0-08`'s deliverable. The infrastructure half is verified here; the
  health-check half is verified in `P0-08`.

## Decisions worth recording

- `compose up --wait` treats *any* exited container as a failure, including
  a one-shot that exits 0, so `infra:up` waits on the three long-running
  services and runs `minio-init` as a separate `compose run --rm`.
- Integration tests use Testcontainers rather than the compose stack, so a
  test run never touches development data and CI needs only a Docker daemon.

## What the next task/session needs to know

- Bucket creation in test setup uses the `mc` binary *inside* the MinIO
  container (`container.exec`), deliberately: using the S3 SDK there would
  import a provider SDK outside `packages/storage-adapter` (`ADR-001`).
- `TEST_MINIO` in `global-setup.ts` holds the test credentials and bucket
  name; `P0-07`'s S3 adapter tests read them from there.
- The Dockerfile does a full workspace `pnpm install`. When `apps/` and
  `sdks/` exist, `.dockerignore` excludes them; if `--frozen-lockfile`
  starts rejecting the missing importers, switch to a filtered install.
