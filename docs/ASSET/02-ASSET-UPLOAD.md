# 02 - Asset Upload

> Category: **Asset Management** (`docs/ASSET/`) &nbsp;|&nbsp; Status: Final (v1 -- direct path; presigned P2-03, remote URL P2-04) &nbsp;|&nbsp; Owner: TBD

## Purpose

What happens, in what order, when an original enters the platform -- the
lifecycle side of `docs/API/11-UPLOAD-API.md`.

## Category Mandate

An 'asset' is the platform's core resource: an uploaded original plus its
metadata, versions, and generated derivatives. These documents define the
full asset lifecycle -- identity, upload, versioning, tagging, organization,
duplication, deletion, and restoration -- independent of any single consumer
application's data model.

---

## Ingestion paths

| Path | Task | Validation |
|---|---|---|
| Direct multipart (`POST /v1/projects/{id}/assets`) | `P2-02` | before anything is written |
| Presigned direct-to-storage | `P2-03` | after the bytes land, before the asset leaves `pending` |
| Remote URL | `P2-04` | after the fetch (SSRF-guarded), same checks |

Every path runs the same checks (`docs/IMAGE-PROCESSING/02`).

## Direct upload, step by step

1. Authenticate; check `asset:create`; enter the project (in coverage, not
   archived).
2. Read the multipart form (one file, bounded while streaming).
3. If `Idempotency-Key` is present, claim it (`docs/API/08`); a retry of
   the same request replays the first response.
4. **Validate the bytes** (`inspectImage`): size, magic bytes, header
   dimensions. Nothing is written if this fails.
5. Check `folder_id`, if given, is a folder of this project.
6. In **one transaction**: insert the asset (`pending`), insert version 1
   (`ready`, with its facts and storage key), store the original, point the
   asset at the version and set it `processing`. A storage failure rolls
   the rows back (`503 storage_unavailable`); the original is only ever
   referenced by a committed row.
7. Respond `201` with the asset.

Phase 3 moves the asset from `processing` to `ready` (or `failed`) once
processing completes.

## Identity

`asset_id` and `version_id` are ULIDs generated by the platform, never
reused (ADR-003). The object key is built from them
(`docs/STORAGE/04`); the client's filename is display text only.
