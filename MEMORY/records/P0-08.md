- **Date:** 2026-09-21
- **Author:** Agent session (Claude Opus 5, Claude Code)

## What was built

- `services/api/src/app.ts` -- `buildApp()` (Fastify 5, `ADR-020`): request
  id generation, W3C trace continuation, one redacted completion log line per
  request, `/healthz`, `/readyz`, the `/v1` prefix, `404 route_not_found`.
- `services/api/src/server.ts` -- config first; `--check-config`; logger,
  database, Redis, lazily-loaded storage adapter; graceful `SIGTERM`/`SIGINT`.
- `services/api/src/readiness.ts` -- PostgreSQL `select 1`, Redis `PING`,
  storage `stat` on a probe key, each bounded by a 2 s timeout.
- `packages/errors` -- the success/error envelopes;
  `services/api/src/http/respond.ts` -- the only way handlers write bodies.
- `packages/cache` -- `createRedisClient()`.
- `scripts/check-bundle-deps.mjs`, run by `pnpm build`.

**Verified end to end, three ways:** the unit suite via `app.inject`; the
built `dist/server.js` against the compose PostgreSQL/Redis and a local
storage directory (`/healthz` 200 with `x-request-id` and `traceparent`,
`/readyz` all ok, `/v1/unknown` 404 envelope); and the Docker image in
production mode (`/readyz` ready, clean shutdown on `SIGTERM`).

This task also closes `P0-05`'s deferred clause: a request produces one
correlated completion line joinable by `trace_id` (tested).

## Deviations from the spec

- `P0-09` owns the error-code taxonomy and the error handler; this task
  added only the envelope and `route_not_found`.
- `docs/ENGINEERING/05`'s layer templates still use a placeholder framework.
  They will be rewritten from the first real module (`P1-02`), so the
  template is copied from working code rather than invented.

## Decisions worth recording

- `ADR-020` -- Fastify, with an addendum to `ADR-018` on bundle dependencies.
- Liveness checks nothing external; readiness checks every dependency.
- Timestamps are RFC 3339 with **millisecond** precision (what
  `Date#toISOString` produces), fixed in `docs/API/01`.

## Bugs found and fixed

1. **CI failed on `main` (build)**: a `db` <-> `test-utils` package cycle.
   Fixed on `fix/turbo-cycle` before resuming: the migration test moved into
   `test-utils`, the `^build` edge was dropped, and `pnpm verify` now runs
   `build` -- the local gate had not.
2. **A PostgreSQL restart would crash every api process.** Idle pooled
   connections receive `FATAL 57P01`; `pg.Pool` then emits `error`, and an
   unhandled `error` event kills Node. Found by the readiness test stopping a
   real PostgreSQL. The pool and the Redis client now both have handlers.
3. **The built bundle could not start** ("Cannot find package 'pg'"): the
   bundle imported third-party packages that were dependencies of workspace
   packages, not of the service. Every service now declares them directly,
   and the build fails if one is missing.
4. **Every storage SDK loaded at startup** even on local disk. The factory
   now imports only the configured provider; network adapters moved to
   subpath exports.
5. `tsup` tried to bundle `ssh2`'s native modules; third-party packages are
   now never bundled.

## What the next task/session needs to know

- New routes register inside the `/v1` plugin in `app.ts`.
- `app.ts` casts the logger to `FastifyBaseLogger` deliberately (commented).
- A new third-party import in any package used by a service must also be
  added to that service's `dependencies`, or `pnpm build` fails.
- Fastify's `requestIdLogLabel`/`disableRequestLogging` top-level options are
  deprecated; they are set via `LogController`.
