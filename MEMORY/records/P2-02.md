## What was built

- `packages/image-engine/src/inspect.ts` -- `inspectImage`: size, magic
  bytes (the type comes from the content only), header-only dimensions via
  libvips metadata (nothing decoded), decoder/sniff agreement, SHA-256.
  Accepted: JPEG, PNG, WebP, AVIF, GIF, TIFF; limits 25 MiB, 16,384 px per
  side, 50 MP, 100 frames. SVG refused. sharp 0.35.4 / libvips 8.18.6.
- `POST /v1/projects/:project_id/assets` (multipart, `asset:create`) and
  `GET /v1/projects/:project_id/assets/:asset_id` (`asset:read`):
  `services/api/src/modules/assets/` (routes, service, repository, mapper,
  module), `http/multipart.ts` (explicit limits; the stream is cut at the
  size limit), `modules/tenancy/project-access.ts` (project in coverage,
  in the key's application, not archived for writes -- else 404/409),
  `modules/folders/folder.repository.ts`.
- Upload flow: validate first; then one transaction inserts the asset and
  version 1 (ready, with facts and storage key), stores the original, and
  sets the asset `processing`. Storage failure -> 503 and no rows.
- Idempotency (step 3): migration `20260921T1700_create_idempotency_keys`,
  `modules/idempotency/` -- claim by insert-on-conflict, replay with
  `Idempotent-Replayed: true`, 409 on key reuse with a different request or
  while in progress, key released on failure, 24 h TTL.
- Multipart error codes mapped in the error handler.
- `AppOptions.assets` is required, so the route gate always sees the asset
  routes; isolation cases added for both routes (multipart supported by
  the harness).

## Definition of Done evidence

- **Spoofed type rejected**: HTML named `photo.jpg` sent as `image/jpeg` ->
  `415 unsupported_media_type`, no rows (HTTP test); SVG/HTML/zip/PDF
  rejected by bytes (unit).
- **Absurd declared dimensions rejected before decode**: a crafted 71-byte
  PNG declaring 100000x100000 -> `422 image_dimensions_exceeded` in
  milliseconds, no rows, no stored object (unit and HTTP).
- **Isolation test present**: both routes in `ISOLATION_CASES`; the P1-06
  gate passes.
- Also tested: happy path facts and storage key, hostile filename reduced
  to display text, missing file / unknown field, foreign folder, key not
  covering the project, archived project, missing permission, storage
  outage rollback, the three idempotency behaviors.

## Deviations

- Files are buffered in memory (<= 25 MiB) for validation before storing;
  concurrency x 25 MiB is the memory bound. Streaming to storage with
  validation of the head is a later optimization.
- The upload response `status` is `processing`; Phase 3 makes it `ready`.
