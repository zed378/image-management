- **Date:** 2026-09-21
- **Author:** Agent session (Claude Opus 5, Claude Code)

## What was built

- `packages/tenancy/src/permissions.ts` -- the closed permission vocabulary
  (40 permissions, `Permission` union), the four fixed roles, the
  role -> permission matrix (nested: owner > admin > developer > viewer;
  credentials, members, tenant settings and purge are owner-only,
  SEC-AZ-03), and `effectivePermissions(tenantRole, grants, scope)`
  (application grants cover the application and its projects; project
  grants only that project; grants only add).
- The guard is the route `config.permission` from P1-03, now typed as
  `Permission`: a misspelled permission is a compile error. API-key
  permission lists are validated against the vocabulary (`z.enum`), and the
  `provision` CLI rejects unknown permissions.
- `docs/SECURITY/08-RBAC.md` Final, with the matrix table.

## Definition of Done evidence

- **The matrix in `docs/SECURITY/08` matches the test table exactly** --
  mechanically: `permissions.test.ts` parses the document's table and
  compares every role x permission cell (160 cells) with the code, and
  fails if a permission is missing from or extra in the document. Plus:
  roles nest, owner-only set, and every scope rule of
  `effectivePermissions`.

## Deviations from the spec

- The task's `@RequirePermission('asset:delete')` decorator is the
  declarative route `config.permission` (Fastify has no decorators; the
  route contract already makes a missing declaration a registration error).
- User principals (dashboard login) arrive in `P6-09`; they will call
  `effectivePermissions` with the user's role and `role_assignments` rows.
