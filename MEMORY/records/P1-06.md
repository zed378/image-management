- **Date:** 2026-09-21

## What was built

- `buildApp({ onRoute })` -- an observer called for every route as it
  registers (methods expanded), so tests read the real route table.
- `services/api/tests/isolation/coverage.ts` -- `routesMissingIsolation`
  (every `/v1` route with a path parameter, HEAD excluded, needs a case in
  `ISOLATION_CASES`) and `staleIsolationCases` (a case naming a route that
  no longer exists).
- `services/api/tests/isolation-gate.test.ts` -- runs both against the real
  application, in the `verify` job's unit tests.
- `docs/TESTING/08` Final: the map of every automated security property to
  its suite and CI job.

## Definition of Done evidence

- **Adding a new `:id` route with no isolation test fails CI by
  construction**: the gate test registers `GET /v1/assets/:asset_id` with no
  case and asserts the gate reports exactly that route; on the real app it
  reports nothing missing and nothing stale. The isolation behavior itself
  runs in the `integration` job (`tenant-isolation.int.test.ts`, P1-05).

## Deviations

- The gate runs inside the existing `verify` job rather than as a separate
  CI job: it needs no database, so it fails fastest there.
