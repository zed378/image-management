## Deviations from the spec

- The task said to start non-blocking and track a follow-up to make the
  scans blocking once the baseline is clean. The baseline was cleaned in
  this task, so both are blocking from the start (audit at high/critical;
  moderate/low are reported in the log). There is no follow-up to track.
- CodeQL's result is a code-scanning alert rather than a failed check; the
  merge gate is the `security` job. Making a CodeQL alert block is a
  repository ruleset setting, not a file in this repo.

## Decisions worth recording

- Gitleaks allowlists values, never paths: a path allowlist would hide a
  real secret later added to the same test file.
- gitleaks runs from its container image, not `gitleaks-action` (which
  needs a license key for organization repositories).
