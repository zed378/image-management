## 5. The protocol

Heading:

```
The URL format is a specification
```

Body:

```
Every parameter, every accepted value, every default, and the exact order
the pipeline applies them is written down and versioned. Two URLs that mean
the same thing produce the same cache key, the same stored object, and the
same bytes — and there are conformance vectors that prove it.

That matters the first time a vendor changes a default underneath you.
```

Code example (taken verbatim from
`docs/IMAGE-DELIVERY-PROTOCOL/03-TRANSFORMATION-URL-SPECIFICATION.md`):

```
These four requests are one derivative, one cache entry, one stored object:

  ?w=800&h=600&fit=cover&g=center&q=80&f=auto
  ?h=600&q=80&f=auto&fit=cover&w=800&g=center
  ?width=800&height=600&fit=crop&position=center&quality=80&format=auto
  ?w=800&h=600&fit=cover&g=center&q=80&auto=format

Canonical form:

  dpr=1&f=avif&fit=cover&g=center&h=600&q=80&w=800
```

Caption:

```
Parameter names follow CSS object-fit for fit modes and the common
short forms every major provider agrees on. If you have written imgix or
Cloudinary URLs before, you already know ours.
```

Link: `Read the full specification →` -> `/protocol`

**PROOF:** `docs/IMAGE-DELIVERY-PROTOCOL/03` and `04` are Final
(`ADR-012`, `ADR-013`, `ADR-014`). Claimable today. The conformance-vector
claim needs `P3-10`.

## 6. Migration

Heading:

```
Your existing URLs already work
```

Body:

```
imgix and Cloudinary parameter names are accepted as aliases. fm becomes f,
fit=crop becomes fit=cover, c_fill becomes fit=cover, fo becomes g — and you
do not have to change any of them, because both spellings resolve to the
same canonical form and the same cache key.

Change the hostname. Keep the query strings.
```

## 7. Why it is fast

Heading:

```
Fast because of how it caches, not because we say so
```

Body:

```
Two URLs asking for the same image produce one cache key. That sounds
obvious; it is the reason a naive implementation double-generates and
double-stores every derivative, and the reason hit rates collapse.

A request that misses the edge usually still does not transform anything: the
derivative's storage key is computed from the parameters, so the origin looks
for the object directly without touching a database. Only a genuine miss runs
the pipeline, and concurrent requests for the same missing derivative
collapse into one transformation rather than hundreds.
```

Three stat tiles — **placeholders until measured:**

| Tile | Copy |
|---|---|
| 1 | `[[N]]% edge hit rate` / `sustained, production traffic` |
| 2 | `[[N]] ms TTFB` / `cached derivative, p50` |
| 3 | `[[N]] ms` / `cold transform, 12 MP source to 640 px AVIF` |

**PROOF:** tiles 1 and 2 need `P7-05`. Tile 3 needs `P3-01`'s benchmark.
Until all three exist, this section ships as prose only. A percentage nobody
measured is the exact thing this page is trying not to be.

## 8. Security and isolation

Heading:

```
Multi-tenant by construction
```

Four items:

| Item | Copy |
|---|---|
| Isolation | `Every query is scoped to your project at the data-access layer, not only at the API. Another tenant's asset ID returns 404, and there is a test in CI that proves it for every endpoint.` |
| Signed URLs | `HMAC-SHA256 over a canonical request string, with the construction published so any SDK can produce a byte-identical signature. Expiry is enforced before verification.` |
| Metadata | `EXIF is stripped by default, GPS coordinates included. Orientation is applied first, so nothing rotates silently.` |
| Enumeration | `Asset IDs are ULIDs. Nothing in a URL reveals how many assets exist or when they were created relative to each other.` |

Link: `Security documentation →`

**PROOF:** `ADR-003`, `ADR-005`, `ADR-006`, `docs/SECURITY/11`, `12`, and
the `P1-06` IDOR suite. The "test in CI" sentence may not ship before
`P1-06` does.

## Accessibility requirements for this copy

- Every image in the hero and the converter has a real `alt` describing the
  photograph, not the transformation. `alt="Mid-century armchair, front
  three-quarter view"`, not `alt="example image"` or `alt="640px AVIF"`.
- The URL bar is a labelled form control, keyboard-editable, with the
  parameter fields reachable by `Tab`.
- Byte counts and dimensions are real text, never rendered inside an image,
  so a screen reader and a search engine both get them.
- Parameter changes announce the result via a polite live region:
  `Delivered 640 by 427 pixels, AVIF, 38 kilobytes.`
- Heading levels descend without skipping: one `h1`, then `h2` per section.
